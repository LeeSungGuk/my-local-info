- 현재 판단이나 실행에 필요한 규칙을 선택하고, 후속 구현·테스트·Git 작업의 규칙을 미리 읽지 않도록 했습니다.
- 대화에 최신 전문이 제공됐거나 같은 세션에서 확보한 지침은 재사용합니다. 파일 변경 또는 컨텍스트 압축으로 필요한 내용이 사라진 경우에만 재확인합니다.
- 링크를 자동 로딩 목록으로 취급하지 않고, 현재 작업에 맞는 자료와 선택한 문서가 현재 행위에 필수로 지정한 자료만 읽도록 했습니다.
- 중요한 불확실성, 작업 범위·완료 기준, 독립 목표의 분리·순서·승인 범위를 각각 별도의 선택 조건으로 구분했습니다.
- 기존 문서 수정이나 스킬 기본 경로 사용만으로 경로·보관 규칙을 추가하지 않도록 했습니다. 역할 분류, 미정 경로, 경로 예외, 이동·이름 변경에는 관련 기준을 적용합니다.
- 행위, 경로, 쓰기 여부, 승인, 보안, 외부 경계, 위임 방식이 바뀌면 새로 필요한 지침만 추가합니다. 필수 규칙을 누락할 수 있는 고정 파일 수 상한은 두지 않았습니다.
- 보안 판단·설계 또는 문서/코드 변경에는 기존 보안 규칙의 공통 1·7절을 적용하고, 작업별 해당 절과 체크리스트 항목을 추가하도록 연결했습니다. 보안 규칙 본문은 변경하지 않았습니다.
- 승인·보안·레거시 보호·코드 marker·Git·외부 호출 경계는 현재 판단이나 행위 전에 적용하도록 유지했습니다. 이 저장소에는 별도 레거시·코드 marker 전용 규칙 파일이 없으며, 별도로 적용되는 지침과 대상 코드의 보호 표시를 확인하도록 명시했습니다.

## 작업 흐름 반영

로컬 참고 자료인 「AI-Native SDLC Playbook」의 Markdown 전문을 분석하고, 필요한 원칙을 기존 규칙에 독립적으로 반영했습니다. 규칙 실행 시 지식문서 원문을 다시 읽는 의존성은 추가하지 않았습니다.

| 입력 | 기본 흐름 |
| --- | --- |
| 외부 요구사항 | 요구사항 확인 → PRD → SRS → tasks → 구현·검증 |
| 내 아이디어 | intent.md → spec.md → plan.md → 구현·검증 |

- `intent`는 해결할 문제, 아이디어, 기대 효과, 제약과 미확정 사항을 정리합니다.
- PRD는 대상 사용자, 제품 범위·제외 범위와 성공 기준을 정리합니다.
- SRS는 구현할 동작, 데이터·인터페이스·제약과 검증 가능한 요구사항을 정리합니다.
- `spec.md`는 intent를 검증 가능한 동작·범위·수용 기준으로 구체화합니다.
- `plan.md`는 spec을 변경 파일·작업 순서·위험·검증 방법으로 구체화합니다.
- `tasks`는 실제 작업 단위, 순서·의존 관계와 완료 확인 방법을 정리합니다. 아이디어 경로에서는 plan 안의 체크리스트로 표현할 수 있습니다.

사용자 확인에 따라 아이디어 경로를 플레이북의 `intent → spec → plan` 순서로 바로잡고, 의도 → 명세 → 구현 계획의 연결 원리와 단계별 완료 기준을 규칙에 추가했습니다. 요구사항·목적이 바뀌면 앞 단계의 문서와 계획을 맞추며, 리뷰·배포·운영 피드백은 기존 승인 범위 안에서 진행하도록 했습니다.

입력 출처뿐 아니라 구체성과 작업 규모에 따라 필요한 단계를 선택하도록 했습니다. 모호한 외부 요청은 intent 수준의 확인부터 시작하고, 이미 구체화된 개인 아이디어는 필요한 spec 또는 plan 단계부터 시작할 수 있습니다. 제공받은 PRD/SRS는 입력으로 활용하고, 필요한 결정과 변경을 기존 프로젝트 문서에 반영합니다.

각 단계는 논리적인 작업 순서입니다. 단계별 새 파일이나 추가 승인을 일괄 요구하지 않습니다. 작은 작업은 대화와 체크리스트로 처리하며, 별도 intent/spec/plan/task 문서는 요청되거나 지속적인 인계에 필요할 때 작성합니다. 기존 PRD/SRS 갱신 조건은 유지했습니다.

단계가 진행된다는 이유로 Git 변경, 외부 호출, 배포 권한이 확대되지 않습니다. 플레이북의 병렬 에이전트, 자동 평가, 자동 커밋·배포 예시는 이번에 활성화하지 않았습니다.
