## 2. 적용 범위와 유지 조건

- 기존 자동 생성 표지의 교체와 앞으로 생성되는 글의 표지 배정을 함께 개선한다.
- 로컬 SVG 방식을 유지한다. 이미지 수집, 생성형 이미지 서비스 도입, 새 유료 서비스와 의존성 추가는 포함하지 않는다.
- 글자 없는 일러스트, 크림색 바탕, 차분한 강조색과 현재 카드 제목 스타일을 유지한다.
- 기존 Markdown 파일은 바이트 단위로 보존한다. 원문 제목·본문·날짜·태그·표지 참조·URL을 바꾸지 않는다.
- 기존 이미지 경로, 목록 정렬, 링크 이동, 상세의 AI 활용·공식 확인 안내를 유지한다.
- 사용자 지정 이미지와 출처를 확인할 수 없는 파일은 보존한다.
- 생성기 개선과 기존 자동 생성 표지 교체를 승인 범위로 적용한다. 커밋·배포는 별도 범위다.

## 4. 주제와 장면

### 4.1 주제 판정

기존 글의 제목·태그와 연결된 큐의 `titleHint`·`angle`·`topicCategory`를 함께 확인해 명시적인 주제 배정표를 만든다. 제목은 게시된 원문을 우선한다. 장소는 문맥 확인에 사용하고, 장소 이름 하나만으로 주제를 바꾸지 않는다.

신규 글의 판정 순서는 기존 ID별 배정 → 핵심 명사·복합 표현 → 보조 태그·분류 → 중립 장면 순서다. 단일 키워드 정규식의 첫 일치만으로 주제를 결정하지 않는다. 큐·글 데이터는 형식과 문자열 여부를 확인한 뒤 사용하고, 문자열을 SVG에 넣을 때 XML 이스케이프를 적용한다.

다음 구분은 반드시 확인한다.

- LP 감상 카페는 음악, 티하우스는 차, 비건 베이커리는 빵·디저트로 분류한다.
- 뮤지엄숍은 전시가 아니라 쇼핑, 식물 편집숍은 일반 쇼핑이 아니라 식물로 분류한다.
- 노을 글의 “노을 맛집” 때문에 음식 그림을 배정하지 않는다.
- 사진 관련 글은 카메라·촬영 장면을 사용하고, 사진이라는 단어만으로 미술 그림을 배정하지 않는다.
- 식물 콘셉트 카페 등 복합 주제는 글의 주된 활동을 확인해 배정표에 근거를 남긴다.

### 4.3 미분류 처리

핵심 주제를 판단하기 어려우면 서울의 공공 공간을 표현한 중립 장면을 사용한다. 자동으로 산책으로 분류하지 않는다. 글 ID, 선택 근거와 미분류 사유를 검토 결과에 남긴다. 초기 181개 글은 개별 검토를 마쳐 사유 없는 미분류가 없도록 한다.

## 5. 다양성 측정과 배정 정책

- **장면 키:** `주제 ID + 장면 ID`. 배색이 달라도 같은 장면으로 센다.
- **그림·배색 키:** 장면 키에 실제 구도 변형과 배색을 더한 값. 단순 반전·확대는 새로운 구도 변형으로 세지 않는다.
- **SVG 비교값:** 접근성 제목·설명, 생성기 식별 속성, 주석과 의미 없는 서식 차이를 제외한 SVG의 비교값. 사람이 보는 차이를 대신하는 지표로 사용하지 않는다.

초기 전체 교체의 수용 목표는 다음과 같다.

1. 게시 날짜를 정규화해 정렬한 최신 12개에서 장면 키가 겹치지 않는다. 날짜가 같으면 글 ID 순으로 판정한다.
2. 교체 대상 전체에서 같은 그림·배색 키를 최대 3개 글까지 사용한다. SVG 비교 결과도 함께 확인해 서로 다른 키로 같은 그림을 중복 등록하지 않았는지 점검한다.
3. 전체 목록의 연속한 카드에서 같은 장면이 반복되지 않는다. 보존 대상 때문에 충족할 수 없는 항목은 별도로 표시하며, 전체 통과로 보고하지 않는다.

신규 배정 시에는 최근 11개 글의 장면과 전체 사용량을 확인한다. 해당 주제 안에서 사용하지 않은 장면을 우선하고, 그다음 그림·배색 조합의 반복이 적은 후보를 선택한다. 적합한 후보가 모두 소진되면 해당 주제의 가장 적게 사용한 조합을 선택하고 `다양성 검토 필요`로 보고한다. 이 예외를 정상 통과로 계산하지 않으며, 다른 주제를 배정하거나 기존 글을 자동 변경하지 않는다.

글 ID와 카탈로그 버전을 선택의 기준으로 사용하고 배정 결과를 자산에 남긴다. 같은 입력·카탈로그·기존 배정 상태로 실행하면 같은 결과가 나와야 한다. 배정된 표지는 이후 새 글 추가·파일 열거 순서·목록 정렬 때문에 다시 선택하지 않는다.

## 7. 이미지·접근성 조건

- SVG 원본은 1600×900, 16:9를 유지한다. 목록·홈의 16:10 중앙 자르기와 1.03배 hover에서도 주요 사물이 남아야 한다.
- 주요 사물은 원본 기준 가로 120~1480, 세로 60~840의 안전 영역 안에 배치한다. 배경 장식은 바깥으로 나갈 수 있다.
- 보이는 `<text>`, `<tspan>`, `foreignObject`, 로고·태그·제목 배치를 추가하지 않는다.
- `<title>`과 `<desc>`에는 해당 글과 실제 그림을 설명하는 접근성 정보를 안전하게 넣는다. 기존 상세의 대체 텍스트가 특정 사물을 설명하는 경우 그 설명과 맞는 장면을 선택한다.
- 기존 `seoul-night-walk-route`의 대체 텍스트는 서울타워와 도심을 설명하므로 해당 요소가 있는 야경 장면을 배정한다. 이를 위해 Markdown을 수정하지 않는다.
- 홈·목록의 장식 이미지 `alt=""`, 상세의 기존 대체 텍스트 처리와 제목 스타일은 유지한다.
- 외부 이미지·폰트 참조, 스크립트, 이벤트 속성, 실행 가능한 외부 입력을 SVG에 넣지 않는다.

## 8. 기존 파일 교체와 실패 처리

기존 파일이 있다는 이유로 새 생성기를 실행해도 자동 교체되지 않는 동작은 유지한다. 전체 교체에는 대상 목록을 먼저 만드는 별도 실행 절차를 사용한다.

대상 목록에는 글 ID·슬러그·기존 경로·기존 해시·주제·장면·배색·선택 근거·보존 여부·예상 새 해시를 기록한다. 기존 생성기로 재현 가능한 파일 또는 개별 확인한 파일만 교체 대상으로 삼는다. 파일 경로나 확장자만으로 소유권을 판단하지 않는다.

검토 시점 이후 해시가 바뀐 파일, 사용자 이미지, 출처가 불분명한 파일, 허용된 표지 폴더 밖 경로, 심볼릭 링크와 잘못된 경로는 교체하지 않고 사유를 보고한다. 모든 대상의 검증이 끝나기 전에는 공개 파일을 쓰지 않는다.

새 SVG는 임시 위치에 생성·검증한 후 적용하고, 원본 파일과 배정 자료를 임시 백업 폴더에 보관한다. 적용 중 실패하면 이미 변경한 파일을 백업에서 복원하고 실패를 보고한다. 백업과 미리보기 보고서는 `public/`에 두지 않는다. 복원도 적용 결과의 해시를 확인해 이후 사용자가 편집한 파일을 덮어쓰지 않는다.

신규 글 생성이 실패하면 기존 정상 표지와 배정을 보존한다. 다양성 후보 소진은 5절의 보고 정책을 따르고, 빈 파일이나 일부 SVG를 정상 표지로 남기지 않는다.

## 10. 운영 캐시 재발 방지 보완

2026-10-21 운영 확인 후 사용자가 다음 보완을 승인했다.

- **COV-09:** 홈·목록·상세가 함께 사용하는 글 로더에서 로컬 `/blog-covers/<이름>.svg`에 파일 내용 기반 버전 쿼리(`?v=<해시>`)를 붙인다. 동일 내용은 빌드·파일 시간 변경에도 같은 주소를 유지하고, 내용 교체 시 새 주소를 사용한다.
- 외부·별도 사용자 이미지 주소는 유지한다. 기존 쿼리와 fragment를 보존하고, 없거나 읽을 수 없는 파일은 기존 참조를 반환한다. 허용 경로 밖 파일과 심볼릭 링크는 읽지 않는다.
- **AC-10:** 내용 변경 시 버전 변경, 동일 내용 시 안정성, 외부 주소·경로 보호, 명시·기본 표지의 목록·상세 일관성을 테스트하고 실제 빌드·화면의 버전 주소를 확인한다. 원본 Markdown·SVG·주제 큐의 해시는 보존한다.

AC-10은 회귀 테스트 6개를 포함한 전체 103개 테스트·린트·빌드와 실제 로컬 화면 검증을 통과했다. 홈 3개·목록 181개·대표 상세에서 버전 주소를 사용하고, 표지 181개의 정상 응답과 버전·내용 일치를 확인했다. 원본 Markdown·SVG·주제 큐 363개는 해시를 유지한다. 변경은 `fix/blog-cover-cache`에 커밋·푸시하고 [PR #3](https://github.com/LeeSungGuk/my-local-info/pull/3)으로 제안했다. 검토·병합·운영 배포 후 확인이 남아 있다.
