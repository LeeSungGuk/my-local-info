## 3. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 홈에 넘기는 데이터가 커진다 | 행사는 요약에 필요한 필드(`id`, `title`, `district`, `venue`, `startDate`, `endDate`, `isFree`)만, 혜택은 구별 수만 넘긴다. 혜택 1,104개 전체를 클라이언트로 넘기지 않는다 |
| 정적 HTML 첫 화면에는 오늘 날짜가 없다 | 기본 색 기준이 날짜와 무관한 혜택 수라 첫 화면부터 색과 수치가 보인다. 행사 수치는 `MAP-05`대로 자리 표시 |
| 행사 목록은 행사가 없는 구의 필터를 전체로 돌린다 | 행사가 1개 이상인 구에만 행사 목록 링크를 둔다 (spec 6절) |
| 홈과 행사 목록의 날짜 기준이 다르다 | 행사 목록은 빌드 날짜, 홈 타일은 브라우저 날짜로 거른다. 브라우저 날짜가 빌드 날짜보다 늦으므로 타일의 행사 수가 목록보다 많아지지 않아, 링크 대상 구에는 항상 목록 행사가 있다 |
| 혜택 목록의 주소 처리 변경이 기존 필터를 깨뜨린다 | 기존 `view` 주소, 분야 칩, 더 보기 동작을 로컬 화면에서 함께 확인한다 |

## 7. 구현 결과와 검증

2026-10-30 로컬에서 1절의 파일 5개를 구현했다. 최신 `origin/main`에서 만든 `feat/home-district-tile-map`에 커밋·푸시하고 [PR #8](https://github.com/LeeSungGuk/my-local-info/pull/8)을 만들었다. 병합·배포는 아직 하지 않았다.

### 7.1 구현 내용

- `district-map.ts`는 타일 배치, 색 구간, 구별 정적 정보, 날짜 기준 행사 요약, 링크 규칙을 한곳에 둔다. 클라이언트 컴포넌트와 Node 테스트가 함께 쓰도록 `fs`나 `@/` 별칭 없이 작성했다.
- 홈 섹션은 상황별 코스 아래에 들어가며, 처음에는 구를 고르지 않은 상태로 서울 전체 수치와 안내를 보여준다.
- 혜택 목록의 지역 선택은 화면 상태 대신 주소의 `district` 값 하나로 관리한다. 분야 선택과 `view` 주소는 그대로 동작한다.
- 구 패널의 보조 링크는 줄 폭에 맞춰 나뉘며, 남는 링크가 혼자 좁게 남지 않는다.
- 사용자가 로컬 화면을 본 뒤 타일 배치를 5열×6행에서 빈칸 없는 5열×5행으로 바꿨다. 배치는 구 중심점과 칸 위치의 거리 합이 가장 작도록 계산했다.

### 7.2 명세와 다르게 구현한 점

| 항목 | 내용 |
| --- | --- |
| 진행 중 판단 | `isOngoingEvent`를 직접 쓰지 않고, 볼 수 있는 행사 중 시작일이 오늘 이전인 항목으로 셌다. 결과는 같다. `home-summary.ts`가 `@/` 별칭을 써서 Node 테스트에서 불러올 수 없기 때문이다. spec `MAP-04`도 같은 기준으로 고쳤다 |

### 7.3 검증 결과

| 검증 | 결과 |
| --- | --- |
| `npm test` | 115개 통과. 새 `district-map.test.mts` 10개 포함. 모듈 작성 전 실패(`ERR_MODULE_NOT_FOUND`)를 먼저 확인했다 |
| `npx tsc --noEmit` | 오류 없음 |
| `npm run lint` | 변경 파일 5개는 경고·오류 없음. 전체 실행의 오류 6개는 Git에서 제외된 로컬 `.codex/plugins/` 파일에서 나오며 이번 변경과 무관하다 |
| `npm run build` | 성공. 빌드가 `public/data/search/index.json`의 `isActive` 값을 오늘 기준으로 다시 만들어 변경했으나, 이번 작업과 무관해 원래대로 되돌렸다 |
| 실제 화면 | `out/` 정적 산출물을 로컬 서버로 띄우고 헤드리스 Chrome으로 31개 항목 통과. 기대값은 화면 코드를 거치지 않고 `public/data`에서 따로 계산했다 |
| 보안 8절 | `out/`에서 API 키 이름 검색 결과 없음. 새 환경변수 없음 |

실제 화면 확인 항목. 2026-10-30 최신 `origin/main` 데이터를 기준으로 기능 브랜치에서 다시 확인했다. 행사가 없는 구와 있는 구는 데이터에서 그때그때 골라 확인한다.

- `AC-01`: 상황별 코스 섹션 바로 다음 형제가 구별 지도 섹션이다.
- `AC-02`: 25칸이 빈칸 없이 5열×5행을 채우고, 모든 칸의 가로세로가 같다.
- `AC-03`: 처음 기준은 혜택이고 종로구 타일은 58이다. 행사로 바꾸면 20이 되고 범례가 `8+` 구간으로 바뀐다.
- 링크: 강서구(가이드·행사 없음)는 혜택 목록이 주요 링크이고 행사 목록 링크가 없다. 종로구는 가이드·행사·혜택·먹거리 페이지 순서다. 은평구(가이드 없음, 행사 있음)는 행사 목록이 주요 링크이고 먹거리는 새 창 카카오맵이다.
- 행사 목록 연결: `/events/?district=은평구`가 “은평구 행사 7건”으로 열린다.
- `AC-06`: `/benefits/?district=종로구`는 종로구 선택·58건으로 열린다. 분야를 골라도 주소의 지역이 유지되고, 강남구를 고르면 주소가 바뀌며, 전체 지역을 고르면 `district`가 빠진다. 없는 지역 값은 전체 1,104건으로 열린다. `view=closing-this-week`와 함께 써도 보기 안내가 유지된다.
- `AC-07`: 390px 폭에서 문서 폭 390px, 가장 작은 타일 65.2px.
- `AC-08`: 포커스한 마포구 타일에서 Enter로 선택되고 포커스 외곽선이 보인다.

브라우저 확인 스크립트는 세션 임시 폴더에서 실행했고 저장소에는 넣지 않았다.
