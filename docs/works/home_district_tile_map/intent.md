## 문제와 배경

PRD 6.3은 사용자가 특정 구를 기준으로 행사, 혜택, 먹거리를 함께 보는 시나리오를 정의한다. 현재 홈에는 구 단위 진입점이 없다. 홈은 히어로·상황별 코스·추천 글·오늘의 서울 요약·행사·혜택 순서로 구성되고, 구별 탐색은 헤더와 푸터의 `/districts` 링크에서만 시작한다. `/districts`는 가이드가 있는 10개 구만 카드로 보여주므로, 나머지 15개 구에 사는 사용자는 홈에서 자기 구를 고를 방법이 없다.

2026-10-30 로컬 데이터 기준 구별 분포는 다음과 같다. 행사 수는 빌드·조회 날짜에 따라 달라지는 참고값이다.

| 항목 | 현재 상태 |
| --- | --- |
| 구별 가이드 | 25개 구 중 10개 구 (종로·중·마포·성동·용산·강남·송파·영등포·서대문·광진) |
| 볼 수 있는 행사 | 2026-10-22 수집 135개 중 81개. 구별 0~11개, 0개인 구 3곳 (관악·양천·서대문) |
| 구 혜택 | 구별 15~108개. 서울 전체 대상 혜택 117개는 별도 |
| 먹거리 후보 | 구별 12곳 (수집 설정의 구별 상한) |

## 시안 비교와 결정

같은 데이터로 실제 행정구역 경계 지도와 타일 지도를 함께 시안으로 만들어 비교했다.

| 기준 | 실제 경계 지도 | 타일 지도 |
| --- | --- | --- |
| 한눈에 서울로 읽히는가 | 바로 읽힌다 | 위치 관계만 근사한다 |
| 휴대폰에서 누르기 | 중구·동대문구처럼 작은 구는 어렵다 | 25개 구가 같은 크기라 쉽다 |
| 외부 데이터 | 구 경계 좌표가 필요하다 | 필요 없다 |
| 라이선스 | 시안에 쓴 공개 변환본은 README에 Apache 2.0을 표기하지만 LICENSE 파일이 없고, 원본(통계청 2013 센서스용 행정구역경계) 이용 조건을 따로 확인해야 한다 | 자체 배치라 확인할 외부 조건이 없다 |

광고가 붙은 사이트라 지도 데이터의 상업적 이용·출처 표시·변경 허용 조건을 확인해야 하고, 모바일 조작성도 타일 쪽이 낫다. 사용자가 타일 지도로 결정했다.

## 대상 사용자

- 사는 구나 갈 구를 기준으로 행사·혜택·먹거리를 함께 보고 싶은 사람 (PRD 5)
- 가이드가 없는 구에 살아 지금 홈에서 자기 구를 찾기 어려운 사람
- 휴대폰으로 홈을 훑어보는 사람

## 기대 결과

- 홈에서 구를 한 번 눌러 그 구의 행사·혜택·먹거리 수와 대표 행사를 바로 본다.
- 선택한 구의 가이드나 해당 목록으로 이어서 이동한다.
- 25개 구 모두 진입점이 있고, 가이드가 없는 구도 막다른 길이 되지 않는다.
- 휴대폰에서도 모든 구를 쉽게 누를 수 있다.

## 범위

포함한다:

- 홈의 새 섹션: 25개 구 타일 지도와 선택한 구의 요약
- 이미 수집된 행사·혜택·먹거리 데이터와 구별 가이드 정보의 재사용

포함하지 않는다:

- 실제 경계 지도, 외부 지도 SDK와 지도 데이터
- 위치 기반 추천, 계정·개인화 (PRD 7 제외 범위)
- 가이드가 없는 15개 구의 새 에디토리얼 가이드 작성
- 새 데이터 수집이나 외부 API 추가

## 유지할 조건

- 정적 배포 구조를 유지하고, 새 의존성 없이 구현하는 것을 기본으로 한다.
- 기존 홈 섹션, 데이터, 페이지 주소와 한국어 문구를 유지한다.
- 현재 디자인(크림색 바탕, 먹색 버튼, 사이트 색 토큰)을 따르고 모바일 배치를 함께 맞춘다.
- 행사의 ‘볼 수 있음’ 판단은 기존 `filterVisibleEvents` 기준과 같게 하고, 오늘 날짜는 홈 행사 섹션처럼 `useTodayInSeoul`로 브라우저에서 계산한다.
- 수치는 공공데이터 기반 참고값으로 표현하고 출처 표시를 유지한다.
