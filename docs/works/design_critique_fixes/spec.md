## 2. 요구사항

| ID | 요구사항 |
| --- | --- |
| `FIX-01` | 검색은 ‘서울’, ‘서울시’, ‘서울특별시’, ‘곳’, ‘갈만한’, ‘가볼만한’을 검색 단어에서 뺀다. 검색어가 이 단어들뿐이면 그대로 검색한다 |
| `FIX-02` | 남은 단어가 2개 이상이고 모든 단어가 맞는 결과가 없으면, 한 단어 이상 맞는 결과를 많이 맞은 순서로 보여주고 검색 화면에 그 사실을 알린다. 모든 단어가 맞는 결과가 있거나 단어가 하나면 지금처럼 모두 맞는 결과만 보여준다 |
| `FIX-03` | 검색 결과가 없을 때 상황별 가이드 3개로 가는 링크를 보여준다 |
| `FIX-04` | 홈 히어로의 상황 바로가기는 각 상황 페이지(`/situations/{slug}`)로 이동하고 외부 이동 표시 ↗를 쓰지 않는다 |
| `FIX-05` | 이번 주 마감 혜택이 0개이면 홈 요약 카드는 그 사실을 알리고 전체 혜택으로 연결한다. 혜택 페이지의 ‘이번 주 마감 혜택’ 빠른 링크는 숨긴다. 이 보기로 들어와 결과가 없으면 원인(이번 주 마감 혜택 없음)과 전체 혜택 링크를 보여준다 |
| `FIX-06` | 구 페이지는 `district`가 그 구 이름과 같은 행사·혜택만 보여준다. 상단 수치는 전체 개수이고, 서울 전체 대상 혜택 수와 목록 링크를 따로 보여준다. 구별 가이드 목록의 행사 수는 `/events`와 같은 볼 수 있는 행사 기준이다 |
| `FIX-07` | 행사·혜택 데이터가 비었을 때 수집 스크립트 이름이나 실행 방법을 보여주지 않고, 사용자가 갈 수 있는 다른 정보를 안내한다 |

## 3. 수용 기준

| ID | 기준 | 확인 방법 |
| --- | --- | --- |
| `AC-01` | `서울 아이와 갈만한 곳` 검색 결과가 1건 이상이다 | 단위 테스트, 화면 |
| `AC-02` | `성동구 무료 전시` 검색 결과가 1건 이상이고 일부 단어 결과 안내가 보인다. 세 단어 중 두 단어가 맞는 결과가 한 단어만 맞는 결과보다 앞선다 | 단위 테스트, 화면 |
| `AC-03` | 한 단어 검색과 모든 단어가 맞는 결과가 있는 검색은 기존 규칙과 같은 결과를 낸다 | 단위 테스트 |
| `AC-04` | 홈 히어로 바로가기 3개가 `/situations/kids`·`/situations/rainy-day`·`/situations/free`로 이동하고 ↗가 없다 | 화면 |
| `AC-05` | 이번 주 마감 혜택이 0개일 때 홈 카드는 안내 문구와 ‘전체 혜택 보기’를 보이고, `/benefits`에는 해당 빠른 링크가 없으며, `/benefits?view=closing-this-week`의 빈 화면이 원인과 전체 혜택 링크를 보인다 | 화면 |
| `AC-06` | `/districts/mapo`의 혜택 카드가 모두 마포구이고, 구 혜택 수가 홈 지도의 마포구 혜택 수와 같으며, 서울 전체 대상 혜택 수가 따로 보인다 | 단위 테스트, 화면 |
| `AC-07` | `/districts/jung` 행사에 중랑구 행사가 없고, 상단 행사·무료 행사 수가 홈 지도의 중구 수와 같다 | 단위 테스트, 화면 |
| `AC-08` | `/districts`의 행사 수가 `/events` 전체 수와 같다 | 화면 |
| `AC-09` | 행사·혜택 데이터 없음 화면 코드에 `node scripts` 안내가 없다 | 코드 검색 |
| `AC-10` | `npm test`, `npm run lint`, `npm run build`가 통과한다 | 명령 실행 |

## 4. 제외 범위

- 검색 결과 카드, 구 페이지 카드, 버튼 모양 변경 (4단계)
- 상황별 페이지에 실제 행사 목록을 붙이는 기능 (별도 제안)
- 한 글자 검색어(예: ‘비’)가 너무 많이 맞는 문제
- 혜택 데이터의 마감일 수집 개선
