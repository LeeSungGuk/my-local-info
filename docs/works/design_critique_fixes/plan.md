## 3. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 일부 단어 결과가 엉뚱한 항목을 보여줌 | 모든 단어가 맞는 결과가 없을 때만 쓰고, 많이 맞은 순서로 정렬하고, 화면에 일부 단어 결과임을 알린다 |

## 5. 구현 결과와 검증

### 5.1 구현 내용

- 검색: 군더더기 단어를 빼고, 모든 단어가 맞는 결과가 없을 때만 일부 단어 결과를 많이 맞은 순서로 보여준다. `searchItems`가 결과와 일치 방식(`all`·`partial`)을 함께 돌려주고, 기존 `filterSearchItems`는 같은 결과를 돌려준다. 검색 화면은 일부 단어 결과일 때 안내 문구를, 결과가 없을 때 상황별 가이드 3개 링크를 보여준다.
- 홈 히어로: 상황 바로가기 3개를 상황 페이지로 연결하고 ↗ 대신 →를 쓴다.
- 이번 주 마감 혜택: 판단 규칙을 `isBenefitClosingThisWeek` 하나로 묶어 홈 요약·혜택 페이지·혜택 목록이 함께 쓴다. 0개면 홈 카드는 “이번 주에 마감되는 혜택은 없습니다”와 ‘전체 혜택 보기’(`/benefits`)를 보이고, 혜택 페이지 빠른 링크를 숨기며, 이 보기의 빈 화면은 원인과 전체 혜택 링크를 보인다.
- 구 페이지: `filterByDistrict`(구 이름 일치)로 행사·혜택을 고른다. 상단 수치는 전체 개수이고 ‘연결 혜택’을 ‘구 혜택’으로 바꿔 “서울 전체 대상 N건 별도”를 덧붙였다. 혜택 영역 제목을 ‘{구} 생활 혜택’으로, 상단 링크를 그 구의 혜택 목록(`/benefits?district=`)으로 바꾸고, 서울 전체 대상 혜택 수와 목록 링크를 아래에 둔다. 홈 지도도 같은 `isSeoulWideBenefit`을 쓴다.
- 구별 가이드 목록: 행사 수를 볼 수 있는 행사 기준으로 바꿨다.
- 데이터 없음 화면: 행사·혜택 페이지에서 수집 스크립트 안내를 빼고 다른 정보로 가는 링크를 넣었다.

### 5.2 명세와 다르게 구현한 점

- 혜택 페이지의 데이터 없음 화면에도 같은 개발자용 안내가 있어 `FIX-07` 범위로 함께 고쳤다.
- 구 페이지 혜택 영역의 상단 링크는 ‘전체 혜택 보기’(`/benefits`)에서 ‘전체 혜택에서 찾기’(`/benefits?district={구}`)로 바꿨다. 행사 영역의 ‘전체 행사에서 찾기’와 같은 방식이다.
